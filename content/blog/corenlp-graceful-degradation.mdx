# Designing for Failure: Graceful Degradation in NLP Pipelines

Linguistic classifiers (like Stanford CoreNLP) are heavy, memory-intensive systems. In production, they are prone to two major issues:
1. **Cold starts**: Booting a CoreNLP pipeline loads word models into memory, taking up to 30 seconds.
2. **Resource exhaustion**: High-concurrency analysis runs can exhaust heap memory, crashing the classifier thread.

If your web application relies on sentiment analysis for immediate calculations, letting the NLP service crash the API is unacceptable. In the **Investment Sentiment Analyser**, we solved this using a **Graceful Degradation** fallback pattern.

## The Architecture: Primary vs. Fallback

We wrapped our NLP classifier in a coordinator service that tracks model health. If the model fails or times out, the service drops back to a simple, fast heuristic-based classifier using regular expressions and a sentiment dictionary.

```
┌─────────────────────┐
│  Text Analysis Req  │
└─────────────────────┘
           │
           ▼
┌─────────────────────┐     No (Error/Timeout)     ┌──────────────────────┐
│ Stanford CoreNLP    │───────────────────────────>│ Regex Heuristics     │
│ Pipeline (Primary)  │                            │ Dictionary (Fallback)│
└─────────────────────┘                            └──────────────────────┘
           │                                                  │
           │ Yes (Healthy)                                    │
           ▼                                                  ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          Sentiment Result                               │
│  (Neutral / Positive / Negative)                                        │
└─────────────────────────────────────────────────────────────────────────┘
```

## The Implementation

Here is how the fallback is orchestrated in Java. We define a unified interface and check health before executing the classification:

```java
public interface SentimentClassifier {
    SentimentResult classify(String text);
}

public class GracefulSentimentService implements SentimentClassifier {
    private final StanfordCoreNLPClassifier primaryClassifier;
    private final RegexDictionaryClassifier fallbackClassifier;
    private boolean isNlpPipelineReady = false;

    public GracefulSentimentService(
        StanfordCoreNLPClassifier primary, 
        RegexDictionaryClassifier fallback
    ) {
        this.primaryClassifier = primary;
        this.fallbackClassifier = fallback;
        initializePrimaryAsync();
    }

    private void initializePrimaryAsync() {
        CompletableFuture.runAsync(() -> {
            try {
                primaryClassifier.initialize();
                isNlpPipelineReady = true;
            } catch (Exception e) {
                // Log and keep isNlpPipelineReady = false
            }
        });
    }

    @Override
    public SentimentResult classify(String text) {
        if (isNlpPipelineReady) {
            try {
                return primaryClassifier.classify(text);
            } catch (Exception e) {
                // Gracefully degrade upon runtime error
                isNlpPipelineReady = false; 
            }
        }
        return fallbackClassifier.classify(text);
    }
}
```

## The Fallback Lexicon Heuristic

The fallback class compiles a dictionary of known financial sentiment terms (e.g., `profit`, `growth`, `crash`, `slump`) and performs a simple regex match to tally positive vs. negative counts:

```java
public class RegexDictionaryClassifier implements SentimentClassifier {
    private final Set<String> positiveWords = Set.of("growth", "profit", "surge", "gain");
    private final Set<String> negativeWords = Set.of("crash", "slump", "loss", "decline");

    @Override
    public SentimentResult classify(String text) {
        String cleaned = text.toLowerCase();
        int score = 0;
        
        for (String word : positiveWords) {
            if (cleaned.contains(word)) score++;
        }
        for (String word : negativeWords) {
            if (cleaned.contains(word)) score--;
        }
        
        if (score > 0) return SentimentResult.POSITIVE;
        if (score < 0) return SentimentResult.NEGATIVE;
        return SentimentResult.NEUTRAL;
    }
}
```

## Performance vs. Accuracy Trade-offs

By introducing this graceful degradation, we navigated a clear engineering trade-off:

| Mode | Latency | Accuracy | Resource Cost |
| :--- | :--- | :--- | :--- |
| **Primary (CoreNLP)** | ~150ms | **88%** (Extracts structural clauses) | High (Needs substantial RAM) |
| **Fallback (Regex)** | **&lt;1ms** | **61%** (Relies on exact match counts) | Negligible (CPU cache friendly) |

In a financial system, having a **61% accurate sentiment indicator online** is infinitely better than having a **0% online system** returning a `500 Internal Server Error`. Graceful degradation keeps the application functional and resilient.
